3. 任意機能・ui_role
==================================================

品目検索、やさしい日本語、多言語:
- CHECKED_PRESENT: URLと確認日の証跡必須
- CHECKED_ABSENT: 調査した公式URL・範囲・確認日の証跡必須
- NOT_CHECKED: 未確認。空URLを不存在に変換しない

ui_roleは独立指定する。collection_channel等から再推論しない。
非CURRENTはHIDDEN、収集外はSORT_BUCKETにしない。

==================================================
4. 区分網羅性レビュー
==================================================

A. 公式総数が明記されている場合: OFFICIAL_COUNT_MATCHED

1. official_category_countへ公式総数を記録する。
2. category_count_evidence_source_idへ総数記載sourceを記録する。
3. category_count_basisへページ・章・記載位置を記録する。
4. CURRENTかつ非EXCLUDED_NOTICEの構造化件数と一致させる。
5. reviewerとreview日を記録する。

B. 公式総数が明記されていない場合: MANUAL_INDEX_REVIEW

1. official_category_countは空欄にする。
2. 公式目次・見出し・索引を先頭から末尾まで全件照合する。
3. reviewed_category_countへ照合した対象見出し件数を記録する。
4. category_count_evidence_source_idへ照合した公式sourceを記録する。
5. category_count_basisへページ、章、開始・終了見出し、除外判断を記録する。
6. reviewed_category_countとCURRENTかつ非EXCLUDED_NOTICEの構造化件数を一致させる。
7. reviewerとreview日を記録する。

公式総数がない場合、構造化件数をofficial_category_countへ転記しない。
照合未完はNOT_REVIEWED、category_count_verified=FALSEとする。

==================================================
7. 共通40品目・2種類の根拠
==================================================

全自治体×40品目のcoverage行を必須とする。

mappingのcategory根拠:
- category_source_id
- category_source_url
- category_source_locator

参照categoryの根拠と完全一致させる。

mappingの品目別根拠:
- item_evidence_source_id
- item_evidence_url
- item_evidence_locator

品目辞典、50音索引、個別注意ページ等、品目判断を直接確認できる同一自治体の
公式sourceを使用する。category sourceと異なってよい。URLはsourceの公式URLと一致し、
locatorには品目行、索引語、ページ、見出し等を記録する。

mapping状態:
- INITIAL_REVIEW_REQUIRED: category根拠のみ。item根拠は空欄
- VERIFIED: ITEM_SPECIFIC、item根拠、reviewer/date必須
- APP_READY: 上記＋全条件枝COMPLETE＋公式品目表記

coverage状態:
- NOT_RESEARCHED: 未調査。item根拠は空欄
- MAPPED_INITIAL: 区分レベル機械抽出。item根拠は空欄
- VERIFIED: 品目別レビュー済み
- VERIFIED_NOT_APPLICABLE: 公式証拠で該当なし
- APP_READY: 全条件枝がアプリ投入可能

reviewed coverageはitem evidence 3列、reviewer、review日を必須とする。

==================================================
8. migration・merge・冪等性
==================================================

1. 旧mapping引用はcategory_source_*へ移す。
2. 未レビュー行にitem evidenceを自動生成しない。
3. 既存ITEM_SPECIFIC手動review証跡だけをitem evidenceへ引き継ぐ。
4. mappingはmapping_id、coverageは自治体・品目pairでmergeする。
5. 手動VERIFIED/APP_READYを優先保持する。
6. migration、build、mergeを各2回実行し、件数・主キー・SHA-256不変を確認する。

==================================================

- header、enum、主キー、MASTER参照

- OFFICIAL_COUNT_MATCHEDの公式総数一致

- QA再計算とmunicipalities同期

構造破損は終了コード1。未完をNOT_REVIEWED / NOT_RESEARCHED / QA_REQUIREDで
正直に表現した状態は構造PASSとする。
