==================================================
2. CORE / REFERENCE・真正性
==================================================

CORE:
- 自治体・区分ID、正式名称、group、level、親、表示順、ui_role
- 代表品目、入れてはいけない物、分類条件、条件外、前処理
- 自治体収集外、安全注意、source、URL、locator、確認日
- rule_status、effective dates

REFERENCE:
- collection_channel
- 袋・容器、粗大、予約、料金、直接搬入、回収拠点、代替処分経路

category詳細は必ずsource_id、公式URL、locatorへ戻って確認する。
公式記載のないCORE詳細は推測せず NOT_STATED_IN_CITED_SOURCE とする。
REFERENCE詳細は公式記載がなければ空欄可。
空欄を埋めるためだけの汎用文は禁止し、validatorで拒否する。

==================================================
3. 公式性・任意機能
==================================================

sourceは公式ドメイン台帳で検証する。
自治体公式ページから案内される外部サービスは公式導線を保持する。

品目検索、やさしい日本語、多言語:
- CHECKED_PRESENT: URLと確認日の証跡必須
- CHECKED_ABSENT: 調査した公式URL・範囲・確認日の証跡必須
- NOT_CHECKED: 未確認。空URLを不存在に変換しない

==================================================
4. 区分網羅性
==================================================

A. OFFICIAL_COUNT_MATCHED
- official_category_count必須
- OFFICIAL_TOTAL証拠必須
- 公式葉区分数と一致
- reviewer/date必須

B. MANUAL_INDEX_REVIEW
- official_category_countは空欄可
- 公式目次・見出し・索引を先頭から末尾まで全件照合
- reviewed_category_count必須
- PRIMARY_INDEX必須、必要に応じSUPPLEMENTAL_INDEX
- reviewer/date必須

C. NOT_REVIEWED
- 全区分体系の公式証拠を取得できない場合に使用する
- category_count_verified=FALSE
- reviewed_category_count、review_id、reviewer/dateを持たせない
- QA_REQUIREDのまま保持する
- 「推定できる」「収集カレンダーに主要区分が見える」だけでMANUAL_INDEX_REVIEWへ上げない

category_review_evidenceは1 source 1行で保持する。
別自治体source、非公式source、存在しないsource、locator欠落、孤立reviewは禁止する。

==================================================
5. 公式粒度と教材UI粒度
==================================================

公式件数はCURRENTかつ非EXCLUDED_NOTICEの公式葉区分を数える。
CURRENT子を持つ投影親は重複計上しない。

教材で親1箱へ束ねる公式子区分:
- classification_level=SUBCATEGORY
- parent_category_id必須
- 子はui_role=REFERENCE_ONLY
- 親はCURRENTかつui_role=SORT_BUCKET

地域限定区分は適用条件を保持する。市内地域差を全国一律の区分へ正規化しない。

==================================================
6. 各Batchの必須7成果物
==================================================

data/research/batches/<batch_name>/ に次を保存する。
1. <batch_name>_municipalities.csv
2. <batch_name>_categories.csv
3. <batch_name>_sources.csv
4. <batch_name>_qa.csv
5. <batch_name>_item_mapping.csv
6. <batch_name>_item_coverage.csv
7. <batch_name>_category_review_evidence.csv

7成果物を持てば研究bundleとして保存できる。
ただしQA_REQUIRED自治体を含むbundleはNEXT_BATCH_GATEを通過しない。
証拠不足を理由にbundleそのものを破棄せず、未完状態を履歴として保持する。

==================================================
7. 共通40品目・mapping
==================================================

全統合自治体×40品目のcoverage行を必須とする。

初期候補生成のPositive evidence:
- 自治体正式名称
- 代表品目

候補生成に使用しない:
- 入れてはいけない物
- 条件外の扱い
- 出す前の処理
- 注意事項

category_source_* は区分体系の根拠。
item_evidence_* は品目別判断の根拠。
INITIAL_REVIEW_REQUIRED / MAPPED_INITIALは品目別確認済みとみなさない。
APP_READYはITEM_SPECIFIC、全条件枝COMPLETE、公式source/url/locator、reviewer/dateを必須とする。

==================================================
8. merge・validation・Gate
==================================================

merge:
- mappingはmapping_id
- coverageはmunicipality_id + internal_item_id
- canonicalはPilot＋全研究bundleのno-loss union
- QA_REQUIREDも研究済み状態としてcanonicalへ保持する
- 手動VERIFIED/APP_READYを再生成で消さない

構造validation:
- header、enum、主キー、MASTER参照
- 公式domain/source
- category参照・親子投影
- category詳細の禁止プレースホルダ
- 区分網羅性・複数source証拠
- QA日付再計算とstatus同期
- mapping/coverage整合

NEXT_BATCH_GATE:
- Pilot・全bundle・canonical構造PASS
- no-loss union
- 全統合自治体QA_PASSED
- merge冪等性
- RED TEAM PASS

APP_READINESS_GATE:
- QA_PASSED
- 40品目すべてAPP_READYまたはVERIFIED_NOT_APPLICABLE
- 品目別公式根拠と条件枝レビュー完備
