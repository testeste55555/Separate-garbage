==================================================
2. CORE / REFERENCE
==================================================

CORE:
- 自治体・区分ID、正式名称、group、level、表示順、ui_role
- 代表品目、入れてはいけない物、適用条件、条件外の扱い、前処理
- 自治体収集外、安全に必要な注意
- source、URL、該当箇所、確認日、rule_status、effective dates

REFERENCE:
- collection_channel
- 指定袋、透明袋、結束等の袋・容器ルール
- 粗大ごみ、予約、料金、直接搬入、回収拠点、代替処分経路

袋や処理の情報が分類結果を変える場合、その条件はCOREの適用条件、
条件外の扱い、前処理へ記録する。REFERENCE欠損だけでQA不合格にしない。

==================================================
3. 公式性・任意機能
==================================================

sourceは公式ドメイン台帳で検証する。
外部サービスは自治体公式導線をofficial_linking_urlへ保持する。

品目検索、やさしい日本語、多言語は次を使用する。
- CHECKED_PRESENT: URLと確認日の証跡必須
- CHECKED_ABSENT: 調査した公式URL・範囲・確認日の証跡必須
- NOT_CHECKED: 未確認。空URLを不存在に変換しない

存在の有無と確認済み状態は分離する。任意機能の不存在・未確認は、
分別COREのQA_PASSEDを単独では妨げない。

==================================================
4. 分別区分・網羅性・ui_role
==================================================

公式見出しを正式名称のまま全件転記し、条件枝と前処理を保持する。

category_count_check_status:
- OFFICIAL_COUNT_MATCHED: 公式総数と構造化件数を機械一致
- MANUAL_INDEX_REVIEW: 公式目次・見出しを人が全件照合
- NOT_REVIEWED: 未確認。category_count_verified=FALSE

verified状態はsource_id、根拠、review日、reviewer必須。
一般文だけでcategory_count_verified=TRUEにしない。

ui_roleは独立指定で、collection_channelやclassification_levelから再推論しない。
非CURRENTはHIDDEN。収集外はSORT_BUCKETにしない。

==================================================
6. 共通40品目mapping
==================================================

全自治体×40品目のcoverage行を必須とする。

- NOT_RESEARCHED: 未調査。不存在ではない
- MAPPED_INITIAL: 区分レベル機械抽出
- VERIFIED: 品目別レビュー済み、APP条件未達
- VERIFIED_NOT_APPLICABLE: 公式証跡で該当なし
- APP_READY: 全条件枝、品目別公式証跡、reviewer/date完備

mapping APP_READY要件:
- evidence_scope=ITEM_SPECIFIC
- branch_review_status=COMPLETE
- 品目別の公式source・該当箇所
- reviewed_date / reviewed_by
- 公式品目表記
- coverage枝数とmapping枝数一致

自治体APP_READY要件:
40 coverage行がAPP_READYまたはVERIFIED_NOT_APPLICABLE。

==================================================

1. Pilotと必要6成果物が揃った全batchを動的発見する。
2. municipalities/categories/sources/qa/mapping/coverageをmergeする。
3. merge中にcategoryからmappingを全面再生成しない。

6. buildとmergeを2回実行し、対象CSVの件数・主キー・SHA-256不変を確認する。

==================================================
8. validationとGate
==================================================

構造validation:
- Schema/header/enum
- MASTER、公式台帳、source/category参照
- rule_status/ui_role不変条件
- 任意機能と区分網羅性の証跡
- mapping条件枝、review証跡
- 自治体×40品目coverage直積
- QA機械再計算と保存値一致

未完了をNOT_RESEARCHED / NOT_REVIEWED / QA_REQUIREDで正しく表現すれば
構造validationはPASSできる。

APP readiness Gate:
- 全自治体QA_PASSED
- 全自治体40品目APP_READYまたはVERIFIED_NOT_APPLICABLE

未完了はAPP_READINESS_GATE_HOLD、終了コード2とする。
