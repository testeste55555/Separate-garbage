2. CORE / REFERENCE・公式性
==================================================

CORE:
- 自治体・区分ID、正式名称、group、level、親、表示順、ui_role
- 代表品目、入れてはいけない物、分類を変える条件、条件外、前処理

REFERENCE:
- collection_channel
- 指定袋、透明袋、結束等の袋・容器ルール
- 粗大ごみ、予約、料金、直接搬入、回収拠点、代替処分経路

sourceは公式ドメイン台帳で検証する。外部サービスは自治体公式導線を保持する。

3. 任意機能・QA日付
==================================================

品目検索、やさしい日本語、多言語:
- CHECKED_PRESENT: URLと確認日の証跡必須
- CHECKED_ABSENT: 調査した公式URL・範囲・確認日の証跡必須
- NOT_CHECKED: 未確認。空URLを不存在に変換しない

QAの確認日は固定値・実行日を使用しない。同一自治体の次の最大ISO日付から導出する。
- 最終確認日
- category_count_reviewed_date
- categoryの確認日
- sourceの取得確認日

QAログは元データから機械再計算し、municipalitiesの確認ステータスへ同期する。

==================================================
4. 区分網羅性・複数source
==================================================

municipalities.category_count_review_idをレビューの安定IDとする。
全証拠をcategory_review_evidenceへ1 source 1行で記録する。

必須列:
- review_evidence_id
- review_id
- municipality_id
- source_id
- locator
- evidence_role

evidence_role:
- OFFICIAL_TOTAL: 公式総数記載
- PRIMARY_INDEX: 手動全件照合の主索引・目次
- SUPPLEMENTAL_INDEX: 補足ページ・別章

別自治体source、非公式source、存在しないsource、locator欠落、孤立reviewは禁止する。

A. OFFICIAL_COUNT_MATCHED
1. official_category_countへ公式総数を記録する。
2. OFFICIAL_TOTAL証拠を最低1件記録する。
3. category_count_basisへ総数位置と構造化対応を記録する。
4. 公式葉区分数と一致させる。
5. reviewerとreview日を記録する。

B. MANUAL_INDEX_REVIEW
1. official_category_countは空欄可。
2. 公式目次・見出し・索引を先頭から末尾まで全件照合する。
3. reviewed_category_countへ公式葉区分の照合件数を記録する。
4. PRIMARY_INDEXを最低1件、必要な補足sourceをSUPPLEMENTAL_INDEXで記録する。
5. category_count_basisへ範囲と除外判断を記録する。
6. reviewerとreview日を記録する。

未完はNOT_REVIEWED、category_count_verified=FALSEとする。

==================================================
5. 公式粒度と教材UI粒度
==================================================

公式件数はCURRENTかつ非EXCLUDED_NOTICEの公式葉区分を数える。
CURRENT子区分を持つ投影親は重複計上しない。

公式子区分:
- classification_level=SUBCATEGORY
- parent_category_id必須
- UIで親へ束ねる子はui_role=REFERENCE_ONLY
- その親はCURRENTかつui_role=SORT_BUCKET

初期mappingはCURRENT子を持つ投影親から生成せず、公式葉へ生成する。
石巻市は「びん類」親1箱へ、公式あきびん4区分を投影する。

==================================================

Positive evidence:

候補生成に使用禁止:
- 入れてはいけない物
- 条件外の扱い

==================================================
8. 共通40品目・category/item根拠
==================================================

全自治体×40品目のcoverage行を必須とする。

category根拠:
- category_source_id / url / locator

品目別根拠:
- item_evidence_source_id / url / locator

品目別根拠はcategory sourceと異なる公式品目辞典・注意ページを使用できる。
INITIAL_REVIEW_REQUIREDとMAPPED_INITIALはitem evidenceを空欄にする。
APP_READYはITEM_SPECIFIC、全条件枝COMPLETE、reviewer/date、公式品目表記を必須とする。

==================================================
9. migration・merge・冪等性
==================================================

1. 旧単数sourceは初回migrationで1証拠行へ移すが、追加sourceを推測しない。
2. 未レビュー行にitem evidenceを自動生成しない。
3. mappingはmapping_id、coverageは自治体・品目pairでmergeする。
4. 手動VERIFIED/APP_READYを候補外でも保持する。
5. canonicalはPilot＋全完成Batchのno-loss unionとする。
6. migrationとmergeを反復し、主キー・件数・SHA-256不変を確認する。

==================================================
10. validation・Gate
==================================================

構造validation:
- header、enum、主キー、MASTER参照
- 公式domain/source、category参照、親子投影
- OFFICIAL_COUNT_MATCHED / MANUAL_INDEX_REVIEW
- category_review_evidenceの複数参照
- QA日付再計算とmunicipalities同期
- mapping証拠・条件枝・review状態
- 自治体×40品目coverage直積

NEXT_BATCH_GATE:
- Pilot・全完成Batch・canonical構造PASS
- canonical no-loss union
- 全自治体QA_PASSED
- merge冪等性
- RED TEAM PASS

標準コマンド: python3 scripts/check_next_batch_gate.py
40品目APP_READYは要求しない。

APP_READINESS_GATE:
- QA_PASSED
- 40品目すべてAPP_READYまたはVERIFIED_NOT_APPLICABLE
- 全品目根拠・条件枝・reviewer・日付完備

標準コマンド: python3 scripts/validate_research.py --app-readiness-gate
未完は終了コード2のHOLDとする。
